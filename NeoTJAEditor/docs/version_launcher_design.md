# 現在の方針（2026-11-10）

独立ランチャーは次の大型アップデートへ延期。
承認済みの画面をアプリ内に実装し、上部「設定」の右隣の「バージョン変更」から開く。
普段の起動時には表示しない。左に検索・スクロール・追加読み込み付きの版一覧、
右に変更内容を常時表示し、下部に「閉じる」「選択版に変更」を配置する。
説明文章は追加しない。

## 今回の実装

- `dialogs/version_change_dialog.py`: GitHubの公開リリースを30件ずつ取得。
  検索中は追加ページも取得する。取得失敗時は自動再試行せず、再操作で取得する。
- 現在と同じ版、EditorとPlayerが揃っていない版は変更不可。試験版は明記する。
- exe版だけで変更する。既存の更新経路を使い、Editor・Player両方の取得成功を必須とする。
- 切替前の設定は設定保存先の `version-backups` へ退避する。
  ランチャー案の版別設定分離ではなく、現行の設定を引き続き使用する方式。
- 既存の差し替え処理では、Playerが使用中などでコピーに失敗すると次回起動時に通知する。
  2本の差し替えを完全に一体で行う方式にはまだなっていない。
- 旧版にはこの選択画面がない。最新版へ戻すには旧版の「更新を確認」を使う。

## 検証

メニュー位置、検索と選択、欠けた配布ファイル、選択版のダウンロードへの引き渡し、
Player取得失敗時の中止、設定退避を対象テストで確認。
公開一覧の実取得も確認。ユーザー設定は変更していない。
実exeのダウングレード・再起動・最新版への復帰は未検証。ビルド・公開保留中のため実行していない。
コミットのみ。push・ビルド・リリース・告知は保留。

## 現行実装からの制約

- `updater.py` は最新リリースを確認し、既存exeを上書きする。旧版には選択画面がないため、独立した入口が必要。
- EditorとPlayerは同じリリースの組にする。片方の取得失敗で部分的に切り替えない。
- `settings.py` はexe隣の設定よりLOCALAPPDATA側の既存設定を優先する。版別ディレクトリだけでは分離できない。
- `child_env.py` のPyInstaller環境変数除去を利用する。旧プロセスの展開先を引き継がせない。

## 実装予定

1. 画面案の確認後、公開版一覧とローカル保存状態を表示する。公開前・下書きの版は出さない。
2. 取得は一時領域へ行い、サイズや実行ファイル形式、公開情報のハッシュがあればその一致を確認してから版別保存先へ確定する。
3. 初回のみ元設定のコピーを引き継ぎ、以後は版別に保持する。既存設定は書き換えない。
4. 旧版にも適用できるよう、子プロセスの設定探索先を分離する。LOCALAPPDATAの分離による素材キャッシュへの影響も検証する。
5. 旧版からの自動更新が保存済みexeを上書きしないよう、管理下での更新動線を設計する。初回コピーでは起動時更新確認を無効化する案。旧版の手動更新への対処も必要。
6. 戻る先・最後に起動した版をランチャー側に記録する。起動失敗で履歴を失わない。
7. Editorからランチャーを開く入口、配布・初回移行方法を追加する。

## 対象を絞った確認

一覧取得失敗時の取得済み版表示、Editor／Player片方の取得失敗、キャンセル、破損ファイル、
同じ版の再利用、設定の分離、戻る履歴、実際の旧版の起動を確認する。
旧版ごとの設定・素材・起動互換性は未検証なので、対応範囲は検証後に確定する。
